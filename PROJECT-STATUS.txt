2) شنو صار مبنياً (بالترتيب الزمني)
--------------------------------------------------------------------
2.1 شاشة الحساب (البروفايل)
- Kotlin + Jetpack Compose فقط، بدون WebView/Flutter/RN.
- الشكل مطابق للصورة المرجعية: فقاعة "Can't decide..." فوق الأفاتار، شارة
  توثيق مرسومة (VerifiedBadge)، الاسم + posts/followers/following، ثم البايو.
- لا توجد أرقام افتراضية إطلاقاً: العدّادات Int? وافتراضها null، وأثناء أول
  جلب تظهر أشرطة Skeleton لامعة، وبعد فشل تظهر "—".
- عداد متدحرج عبر AnimatedContent (بدون clipToBounds) — بلا وميض.
- البيانات الحقيقية من Instagram Graph API بتوكن مدمج في BuildConfig، مع
  مسار بديل: بروكسي Cloudflare Worker.
- التحديث شبه لحظي: كل 5 ثوانٍ، وبسباق بين المسارين (البروكسي يبدأ فوراً، و
  Graph ينطلق بعد 1.2 ثانية إن ما وصل رد)، أول نجاح يُعرض والخاسر يُلغى.
  أقل فاصل بين طلبين ثانيتان، وعند العودة للواجهة ثانية واحدة.
- زر البرغر/الشريط العلوي انحذف نهائياً؛ مافي أي أيقونات فوق.

2.2 كشف شبكة الريلز بالسحب
- PigeonRoot صار VerticalPager من صفحتين: صفحة الحساب (0) وشبكة الريلز (1).
- السحب للأعلى يرفع الحساب بإنميشن إنزلاق ويظهر الشبكة.
- السحب للأسفل من أعلى الشبكة، أو زر الرجوع، يرجّع الحساب.
- مافي شريط تنقل سفلي ولا شاشة إعدادات.

2.3 شبكة الريلز (تصميم إنستغرام)
- شريط أعلى بأيقونة شبكة 3×3 مرسومة بـ Canvas مع خط تحتها.
- 3 أعمدة، خانات مستطيلة قائمة بنسبة 9:16، فواصل 2dp، زوايا 4dp.
- كل خانة: صورة غلاف حقيقية (Crop)، تعتيم سفلي متدرّج، كود الريل، وشارة ✓
  وردية على دائرة داكنة إذا السجل مسجّل في Firebase.
- الضغط على خانة يفتح الريل في إنستغرام (أو التطبيق المناسب).
- الحالة الفاضية: أيقونة ريل + "No reels scheduled yet" + شرح كيف تضيف ريل.

2.4 مشاركة الريل (أهم مسار إضافة)
- ShareReceiverActivity شاشة شفافة مسجّلة لـ ACTION_SEND (نص/صورة/فيديو)،
  ACTION_SEND_MULTIPLE، و ACTION_VIEW لروابط instagram.com/reel|reels و
  tiktok.com و vm/vt.tiktok.com.
- لا تنتقل من إنستغرام: يظهر بوب-أب في منتصف الشاشة فوق إنستغرام مع تعتيم
  خفيف. الكرت فيه: أيقونة ريل بتدرّج إنستغرام + "Reel added" + اسم/كود الريل
  + زرّان: View (يفتح التطبيق على الشبكة) و Close (يرجّعك لإنستغرام).
- الضغط خارج الكرت أو زر الرجوع يغلق أيضاً. الحالة الفاشلة: "No reel found".
- مافي حاجة لصلاحية SYSTEM_ALERT_WINDOW: الاعتماد على Activity شفافة فوق
  التطبيق الذي شارك.
- ShareParser نقي (بدون Android) ويُنظّف روابط إنستغرام إلى
  https://www.instagram.com/reel/<code> ويحذف باراميترات التتبع.

2.5 Firebase Realtime Database (قائمة الريلز)
- القاعدة: https://brainrotpigeon67-default-rtdb.europe-west1.firebasedatabase.app
- الشكل: /reels/<id>.json  (id = UUID للعنصر)
- حقول السجل:
    platform, kind, url, title, thumbnail, registered, source, createdAt
- التنفيذ: FirebaseReels عبر REST فقط (PUT/GET على .json) بدون SDK وبدون
  google-services.json.
- عند المشاركة: الكتابة المحلية فوراً (DataStore) ثم رفع في CoroutineScope على
  مستوى AppContainer (ما ينقطع بإغلاق شاشة المشاركة).
- عند كل فتح للتطبيق: MainActivity ينادي syncFromRemote() فيسحب القائمة،
  يدمجها مع المحلي (سجلات Firebase تتقدّم، الأحدث أولاً)، ويرفع أي عنصر محلي
  ما وصل للقاعدة.
- الحالة الحالية للقواعد: مفتوحة للقراءة والكتابة بدون مصادقة (تم التحقق
  بـ curl: PUT 200، GET 200، DELETE 200). أي شخص يعرف الرابط يقدر يكتب —
  يُقفل لاحقاً عند إضافة المصادقة.

2.6 صور الغلاف (الثمبنيل)
- ReelThumbnails يستدعي oEmbed العامة في إنستغرام:
    https://www.instagram.com/api/v1/oembed/?url=https://www.instagram.com/reel/<code>/
  ويأخذ thumbnail_url (بدون توكن، تم التحقق: HTTP 200 image/jpeg مقاس 640×640).
- الثمبنيل يُطلب وقت المشاركة قبل الرفع ويُحفظ محلياً وفي Firebase (حقل
  thumbnail)، فلما تفتح على جهاز ثاني تطلع الصور فوراً.
- تيك توك: oEmbed العامة أولاً، وإن ما رجّعت صورة (معظم الفيديوهات حالياً ما
  ترجع thumbnail_url) نقرأ صفحة https://m.tiktok.com/v/<id>.html ونأخذ رابط
  الغلاف الموقّع منها (...cover:720:720.jpeg?...) — تم التحقق: JPEG 200 OK.
  روابط vm/vt.tiktok.com و /t/... تُتبع تحويلاتها أولاً لاستخراج كود الفيديو.
- الريلز القديمة بلا صورة: SavedRepository.ensureThumbnails() يجيبها عند فتح
  الشبكة، بحد أقصى 30 محاولة لكل فتح (يشمل تيك توك).
- تحميل الصور: AvatarLoader(client, cacheSize) — كاش ذاكرة 90 صورة للشبكة،
  و12 للأفاتار. صور الخانات تُفكّ بحجم مصغّر (targetSize = 360) لتخفيف الذاكرة.

2.8 نعومة السحب بين الصفحتين (1.6.1)
- الصفحتان تُجهَّزان مسبقاً: beyondViewportPageCount = 1، فما تُبنى الشبكة وسط
  حركة الإصبع (هذا كان سبب التقطيع).
- سلوك إفلات واحد: PagerDefaults.flingBehavior + tween 280ms + عتبة تبديل
  0.16 بدل نابض الافتراضي (فما ترجع الصفحة للوراء).
- تحديث الحساب الدوري (5 ثوانٍ) يتوقف والشبكة ظاهرة عبر
  ProfileViewModel.setPollingEnabled(false)، فلا إعادة رسم/أنيميشن عدادات فوق
  السحب، ويحدّث فوراً عند الرجوع للحساب.
- الخانات: fillMaxWidth + aspectRatio(9/16) صراحةً (مستطيل قائم مضمون).

2.7 اللغة

2.8 تنظيف المشروع (24 نوفمبر)

7) خطة الغد المقترحة (بالأولوية)
--------------------------------------------------------------------
1. تجربة على الهاتف: تثبيت 1.6.1، فتح التطبيق، سحب للأعلى (لازم يكون ناعم
   بدون تقطيع)، مشاركة ريل من إنستغرام وريل من تيك توك، والتحقق من: البوب-أب
   فوق التطبيق، View/Close، ظهور الريل بغلافه في خانة 9:16، وظهور نفس السجل
   في Firebase تحت /reels مع حقل thumbnail.
2. نظام التنزيل (الخطوة الكبيرة القادمة): تنزيل فيديو الريل نفسه وتخزينه
   محلياً، ثم تشغيله داخل التطبيق بدل فتحه في إنستغرام.
   ملاحظة: تنزيل فيديو إنستغرام يحتاج مسار موثوق (بروكسي/طرف ثالث) — نحتاج
   نقرر الطريقة قبل البدء، ونحتاج نرجّع مصدر البروكسي من تاريخ Git إذا احتجناه.
3. تأمين Firebase: إضافة مصادقة (Sign in / Anonymous Auth) وقواعد تقيّد
   القراءة والكتابة، لأن القواعد الحالية مفتوحة.
4. إدارة القائمة: حذف/إعادة ترتيب/تعديل جدولة الريلز من داخل الشبكة (ضغط مطوّل
   مثلاً) — غير موجود حالياً، الإضافة فقط عبر المشاركة.
5. تحسين التحديث: لو بقي إحساس تأخر مع البروكسي، نرجّع مصدر الـWorker من
   تاريخ Git وننشره بـ CACHE_TTL أقصر (5 ثوانٍ) — يحتاج صلاحية Cloudflare
   وwrangler + سر IG_ACCESS_TOKEN.
6. تفاصيل صغيرة: عرض عدد الريلز، ومؤشر مزامنة، وإشعار فشل الرفع (اختياري).
